## User decisions — do not re-litigate

1. **150% display scaling:** On 2026-10-15 the user said they will not use it and explicitly ended the validation loop. Scope its review out, **not** as a pass; never request another DPI-144 capture/ZIP/test unless the user reverses the decision. Actual Windows 100% / DPI 96 is the current target at primary 1456×766 and narrow 1000×700 physical client sizes. A folder named `review-150-viewport` passed 129/129 *unscoped geometry checks at DPI 96* but failed 144-DPI requirement (129/130). The 125%-named capture was also DPI 96; do not claim higher-DPI support from either. Screenshot appearance and pixel parity have not been approved at any DPI.
2. **Make progress without a private photo:** The user has none to supply. Generated JPG/PNG fixtures are allowed for development, CI and benchmarks but are **not** approved real-photo or Windows visual references. If a specific issue's human/real-photo sign-off is genuinely blocked, identify that exact gate and continue another Backlog issue. Do not repeatedly ask for photos or the canceled 150% benchmark.
3. **Keep requests to the user minimal:** When an unavoidable Windows input is needed, list exactly what is lacking, what the result would verify, and the exact PowerShell commands for their *existing checkout*. No long back-and-forth DPI experiments. They want completed, deeply verified issues, not progress-only posts. Report remaining count honestly; do not claim Done on partial evidence.
4. **Windows 11 alpha and updates:** Call the build **alpha**. The user already has an installation; it must receive an **in-place UPDATE**, not a first-time install, with no duplicate app or loss of user saves. `update-alpha.ps1` detects the installed editor and backs up in-install `.isphoto`/`.isbatch` saves. The user can run `git pull origin arena/a3458c15-python-image-switcher` followed by `powershell -NoProfile -ExecutionPolicy Bypass -File .\update-alpha.ps1` from that clone **only when a new build is actually needed**. `-DependenciesOnly` tests without installing. Verify the installed app rather than calling `dist` an installed copy. Keep PR #3 open.
5. **UI concept covers the whole app:** [`docs/mockups/editor-export-concept.png`](docs/mockups/editor-export-concept.png) guides editor and separate Export popup; AI illustration text and buttons are not a functional spec. Export controls appear **only after clicking Export** in a small popup. Editing sidebar has real, named sliders, not a dropdown. Use **Sharpness**, not “Sharpening”; do not add fabricated Whites/Blacks/Clarity/Denoise, silent overwrite/skip, pixel-exact RAW 100% or non-working controls. Empty app versus populated illustration is not a fair pixel comparison.
6. **Keep a numbered, non-destructive batch:** No arbitrary JPG photo-count quota or closed-source feature gate; show import progress after selection. Selecting and hand-editing one photo must not discard the original batch/progress. Give every photo a stable visible number; hand-edited photos are visibly protected from later batch changes **but still included in full-batch export**. Selected-only export is explicit.
7. **Still photographs only:** Nikon NEF and JPG are priority; PNG/JPG screenshots (“SS'ed” product/picture photos) count as stills. MPO/JPG may contain multiple separate still photos; don't silently take only the first. No animation/video or first-frame/page fallback. Background replacement takes supplied high-fidelity still images and simple colors. Current 16-bit NEF background compositing is **not implemented**; reject it honestly without altering the photo rather than silently losing precision.
8. **Fidelity:** Export highest achievable fidelity with lossless rendered masters (8-bit PNG and 16-bit NEF TIFF where supported), `.isphoto` editable copy and untouched original. Never describe JPG re-encoding or NEF rendering as mathematically lossless original capture. Reject unsupported 16-bit PNG/TIFF, CMYK, HEIC/AVIF and other unvalidated precision paths until a tested workflow exists. Keep original bytes, ICC/precision claims and output safety under test.
9. **Performance/GPU:** User reports editor lag and wants RAM efficiency and acceleration beyond 400 photos, from boot in the **installed** app. “GPU ready” or an isolated kernel is not proof of GPU use in supported full-batch edits; record which numbered photos actually used it, CPU fallback, output parity, real file-export timings and representative camera recipes. NEF, other adjustments and PNG/TIFF encoding currently remain CPU. Do not claim broad NEF/ICC/400+ real-camera performance from tiny/generated benchmark fixtures.
10. **Ownership/credentials:** The user wants hidden ownership identification and broadly usable signed credentials, but present implementation only stores **unsigned declared rights inside `.isphoto`**. No watermark, C2PA signature, trusted identity, stripping-resistant universal identifier or legal proof of ownership exists yet. A screenshot/re-export can strip embedded credentials; never promise guaranteed persistence/recognition or misrepresent archive hashes as a signature. Investigate supported derivative formats and Windows packaging before implementing any C2PA plan; NEF was not on the C2PA SDK supported-format list in prior research. Investigate what GitHub “rea” is before considering it; do not assume its function.
