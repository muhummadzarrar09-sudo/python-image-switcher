# Still-photo editor 0.2.0-alpha.5 (incomplete, unsigned alpha)

Launch the existing app (`python src/app.py`), then choose **Still Photo Editor**. This is a separate, in-progress workflow; the existing converter's quality slider and acceptance gate do not govern the editor.

## Working in the source tree

- Import numbered stills including Nikon NEF/JPG and PNG/JPG screenshots, with a cancellable per-file import progress popup. **There is no batch photo-count quota.** Camera JPEGs encoded as MPO (even when named `.JPG`) are collections of still photographs: every frame is imported as its own stable numbered photo, kept in the batch and export, and the unmodified multi-picture original is retained in each `.isphoto` project. This is not animation/video support; actual animated WebP/GIF and multipage TIFF remain rejected rather than taking only the first page. A real camera sample is still needed to verify the user's particular JPGs. 16-bit PNG/TIFF, CMYK and HEIC/AVIF are currently **blocked** until precision and color-management paths are validated. Not every NEF camera/compression has been tested.
- Preserve the numbered batch when selecting one photo; all adjustment sliders are visible by name in the right sidebar (no category selector). The Batch/Selected scope is in the toolbar. Batch sliders update unprotected photos, while the first individual slider/crop/rotation/mask edit locks that photo's current batch values. Locked photos are visibly listed and **are still exported**. Unlocking is explicit.
- The alpha.5 interface follows the [selected export concept](docs/mockups/editor-export-concept.png): a compact numbered photo-thumbnail rail, larger centered image canvas, dark adjustment sidebar and focused dimmed Export overlay. Crop/orientation and background-mask tools have their own toolbar buttons. **Export** opens options for destination, entire-batch versus selected-photo scope, and declared project rights; Escape/Cancel closes without writing anything, and nothing exports until **Export now**. Full-batch export includes protected edits; each export has a lossless master and `.isphoto` project. A working Before/After preview toggle shows the source preview versus the edited render; NEF Before may use its embedded JPEG and is not a pixel-perfect RAW comparison. Sharpness is the actual control name, not the AI mockup's 'Sharpening' text.
- Exposure, brightness, contrast, highlights, shadows, saturation, warmth, tint, sharpness and vignette; crop, 90-degree rotation, horizontal flip. Manual background mask painting/erasing, blur, removal, color and supplied-image replacement for 8-bit source images. **There is no automatic subject detection yet.** Manual brush is provisional, not pixel-accurate refinement.
- `.isbatch` JSON session, and per-photo `.isphoto` ZIP project holding the untouched source, edit recipe, optional supplied background and rendered PNG/TIFF master. SHA-256 checks detect corruption, **not creator identity**. Opening a project verifies assets and requires selecting a durable directory for the extracted original/master; save the session separately if desired.
- Export lossless PNG for 8-bit decoded stills, and 16-bit RGB TIFF for processed NEF. Files are numbered; existing exports are refused rather than overwritten. Source files are never rewritten. ICC profile is carried for Pillow sources when available; NEF TIFF is tagged with sRGB after rawpy's sRGB demosaic. Preview is downsampled to the canvas and rendered off the Tk UI thread with stale-result suppression; full-size export is unchanged. See [PERFORMANCE.md](PERFORMANCE.md) for repeatable CPU/RAM diagnostics. **GPU acceleration is not implemented yet**; it needs device-specific parity and benchmark validation, not a placebo toggle.

## Important limitations before any full release

- Converting a JPG's *decoded* pixels to PNG is lossless from that point forward; it cannot recover details discarded by the input JPG. Demosaicing a NEF creates a new render, not a byte-identical RAW equivalent. Untouched source bytes remain in `.isphoto`.
- NEF background masks/replacements are blocked **before mutating the edit** instead of silently demoting a 16-bit render to 8 bits. Supplied background images that would have to be upscaled at full export size are also rejected before changing the recipe; dimensions account for EXIF orientation, crop and rotation. Mask clicks are ignored while an updated preview is pending, avoiding stale crop/resize coordinates. Large images over the 100-million-pixel safety ceiling are blocked to avoid exhausting memory or decoding malicious image bombs; **this is a resource-safety guard, not a licensing/photo-count limit**. Memory and performance still need larger-camera testing. Color controls operate on encoded RGB channel values, not in a fully managed linear-light workflow. No local retouch/automatic subject segmentation yet.
- Rights strings are *declared fields in `.isphoto` only*: standard PNG/TIFF exports do not yet carry comprehensive IPTC/XMP copyright, attribution or C2PA. No embedded robust watermark, independently trusted signer, revocation flow, remote recovery, or credential interoperability matrix is implemented. A screenshot can lack original image provenance and can never restore lost information. Do not use the preview to claim ownership verification.
- `.isphoto` is a container, not a new standard image codec. Other apps need the companion PNG/TIFF. Archive checksums do not sign the wrapper, and a signature on an inner image would not automatically sign the wrapper.
- No clean Windows 11 VM installation/UI validation or signed production installer has been performed. `installer.iss` and the GitHub Actions job generate **unsigned alpha installers** (CI uses a Windows runner, not a clean Windows 11 PC); their existence is not a production release gate pass. The alpha is for testing, not trusted ownership/provenance workflows.

## Try and test

```bash
python -m pip install -r requirements.txt pytest
python -m pytest -q tests/test_photo_project.py tests/test_editor_render.py
python src/app.py --editor-self-test  # headless round-trip for packaged executables
python src/app.py                     # opens the desktop app, requires a GUI
```

For Windows 11 alpha update/build/interactive setup, run `powershell -NoProfile -ExecutionPolicy Bypass -File .\update-alpha.ps1` from the checkout. `-DependenciesOnly` runs Python install/tests without packaging or desktop setup. See [BUILD.md](BUILD.md) for prerequisites, manual alternatives and limitations. For the existing converter executable, use the separate legacy `build_exe.py`. The alpha still requires editing/export, uninstall and clean Windows 11 verification with real Nikon camera fixtures; ownership credentials are not ready.
